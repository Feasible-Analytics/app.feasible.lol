Two APIs: one to send events, one to read numbers back. Both are HTTP and JSON, and both are documented here in full — there is no separate paid tier for API access.

Sending events

POST /api/event
Content-Type: application/json

{
  "n": "pageview",
  "d": "example.com",
  "u": "https://example.com/pricing",
  "r": "https://duckduckgo.com/"
}

The response is 202 Accepted as soon as the event is durably buffered, before it reaches the database that will hold it. If we could not use the event, the reason is in the x-feasible-dropped response header and on your ingestion health panel — a beacon cannot act on a status code, so the reason travels in a header instead of a 4xx.

FieldMeaning
nEvent name. pageview, engagement, or your own.
dDomain, matching a registered site.
uThe page URL.
rThe referrer, if any.
pCustom properties, as an object.
$Revenue, as {"amount": …, "currency": "USD"}.

Only pageview and your own event names are billable. engagement is the script's heartbeat and is never counted towards your monthly volume.

Stating attribution for a server-side event

An offline or delayed conversion has no referrer of its own and would otherwise be Direct forever. Send the attribution explicitly and it is used in place of the referrer.

Debugging one request

Send X-Debug-Request: 1 with any event and the response is the fully derived event: the address we resolved and where from, the visitor identifier, the geolocation, the channel, and every field we would store. It is the fastest way to prove a proxy is passing the visitor's address through, and it answers "why did this not count" without a support ticket.

Reading numbers back

POST /api/stats/example.com/query
Authorization: Bearer <api key>

{
  "metrics": ["visitors", "pageviews", "bounce_rate"],
  "date_range": "30d",
  "dimensions": ["visit:source"],
  "filters": [["is", "visit:country", ["US"]]]
}

Every report in the product is this one request with different metrics and dimensions. There is no per-card endpoint and there will not be one: a handler per card is a handler per way for the same number to be wrong.

API keys are created in your account settings, shown once, and stored only as a hash. They carry an hourly rate limit, and the limit is per key so one runaway script cannot starve your dashboard.

Exporting everything

The export gives you every event we hold for an account in a portable format. It works in every phase of an account's life, including a locked or dormant one and including the day before a scheduled deletion. It is your data.
