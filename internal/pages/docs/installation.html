One script tag, on every page you want counted. Nothing else is required — no cookie banner, no consent gate, no build step.

<script defer data-domain="example.com" src="https://feasible.lol/js/f.js"></script>

data-domain must match the site exactly as you registered it. It is how an event is routed to your account, and an event for a domain we do not hold is dropped with a reason you can see on the ingestion health panel — never silently.

Where to put it

Anywhere in <head> or <body>. It is deferred, so it never blocks rendering and never appears in your Core Web Vitals. If your site is a single-page application the script picks up route changes on its own; you do not need to call anything on navigation.

Multiple domains

Give each site its own snippet with its own data-domain. A staging copy pointed at your production domain will mix staging traffic into your real numbers, and there is no way to unpick it afterwards — use a separate site, or exclude the hostname.

Checking it works

Load a page and watch the ingestion health panel. Every event we accept, classify or drop is counted there with a reason. If nothing arrives at all, the three usual causes are a data-domain that does not match, an ad blocker (see proxying), and a content security policy that does not allow the script host.

Server-side events

Anything that happens away from a browser — a webhook, a background job, an offline conversion — can be posted straight to the events endpoint. See the APIs for the payload, including how to state the attribution for an event that has no referrer of its own.
