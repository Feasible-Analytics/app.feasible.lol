One binary and one directory. No Docker, no external database, no queue, and no feature that only exists in the hosted version. The software is AGPL-3.0-or-later.

./feasible db migrate
./feasible serve

That is the whole deployment. serve runs the dashboard, the API, the tracker and ingestion in one process, which is what almost every self-hoster should run.

The data directory

Everything lives under FEASIBLE_APP_DATA_DIR: control.db, one SQLite database per account, the geolocation data, the refreshed bot lists and the salt key. Back up that directory and you have backed up the entire install.

Use ./feasible db backup rather than copying files. It takes a proper consistent snapshot; copying a SQLite file that is being written to gives you a file that looks fine and is not.

Migrations never run on boot

Two processes racing a migration is a classic self-hosting failure, and with one database per account the operation is slow enough that it has to be deliberate and observable. A binary that is newer than its databases refuses to start and tells you to run db migrate.

Configuration

Every variable is documented in .env.sample, with a comment and a default. A variable that is not in that file does not exist — the build fails if the source reads one that is missing. Values resolve from $CONFIG_DIR/<NAME> (for Docker and systemd secrets), then the environment, then .env outside production.

Email

Set FEASIBLE_APP_MAIL_TRANSPORT=smtp and point it at a relay. The default log transport writes rendered messages to tmp/mail/ and sends nothing, which is what makes local development need no mail service at all.

Set FEASIBLE_APP_MAIL_FROM to an address your relay is allowed to send as. A relay rejecting a From address it does not own is the most common reason a self-hoster's mail silently stops.

Billing on a self-hosted install

There is none, and nothing is limited because of it. With no payment provider configured the billing screens say so, the lifecycle clock is never started, and no account is ever locked or deleted for non-payment. The account lifecycle exists to manage the hosted service's own subscriptions, not to enforce anything on you.

Behind a reverse proxy

Set FEASIBLE_INGEST_TRUSTED_PROXIES to your load balancer and nothing else. The default is empty — nobody — because an unconditionally trusted address header lets any visitor forge their own geolocation and split their own fingerprint.

Keep FEASIBLE_APP_INTERNAL_LISTEN on loopback. It serves the salts that can turn a visitor identifier back into an address, and it must not be routable from anywhere.

City-level geolocation

Country-level data is embedded in the binary, so geolocation works out of the box with nothing to download. City-level data is a larger, differently licensed file that is fetched on first run when you supply a key. It is not a paid feature; it is an extra file.
